# Организация проекта

Постоянные узлы и данные сохраняются в .tscn/.tres и редактируются в Godot.
Скрипты отвечают за поведение. Отдельный компонент нужен при самостоятельной
обязанности или повторении; универсальный игровой фреймворк не строим.

## Карта ответственности

| Часть | Ответственность |
| --- | --- |
| scenes/base.tscn + scripts/base.gd | Схрон, результат, настройки и запуск единственного рейда |
| scenes/forest_dusk.tscn | Расстановка, коллизии, патруль, добыча, камера и выход |
| scripts/raid_room.gd + scenes/raid_hud.tscn | Связи актёров/HUD, инструменты F2, завершение рейда |
| scenes/player.tscn / enemy.tscn | Текущие персонажи: физика, поведение, отдельный спрайт/оружие/звук |
| scripts/pixel_actor_visual.gd | Направления/ходьба, вспышка попадания, fallen и контактная тень |
| scripts/weapon.gd + scenes/gun_visual.tscn | Стрельба/патроны отдельно от рисунка оружия |
| scenes/forest_dusk/ | Самостоятельные сцены окружения и lighting.tscn |
| scenes/forest_dusk/dressing.tscn | Сохранённая расстановка новых растений/елей/декораций, независимо от исходных объектов карты |
| assets/art/forest_dusk/ + resources/art/forest_dusk/ | PNG/происхождение, атласы/анимации/шейдеры |
| scenes/loot_container.tscn + Inventory / LootInteraction / ItemUse | Ящик, владение/передача вещей, взаимодействие и применение |
| scenes/loot_menu.tscn + scripts/loot_menu.gd | Интерфейс, без владения предметами |
| scenes/ui/frosted_panel.tscn + resources/ui/ | Размытый фон окна, нейтральная тема; контент остаётся чётким |
| RaidProgress / AudioSettings / DisplaySettings | Независимые сохранения прогресса, громкости и окна |
| tests/fixtures/ | Детерминированная геометрия и мишень для проверки действующих систем |

## Границы

Комната содержит Player, Navigation, GuardSpawns, TestEnemies, LootContainers,
ExtractionZone и HUD. RaidRoom соединяет сигналы; актёры/инвентарь/оружие не знают
имени локации. F2 использует guard_scene из Inspector. Во время игры создаются
только динамические вещи, добавленные враги и краткие эффекты.

После выбора сумеречного леса удалена цепочка наследования через солнечные сцены.
Персонажи и ящик оформлены непосредственно в общих сценах; поведение не скопировано.
Сцены окружения самостоятельны, используют общий WorldCover. PNG не заменены,
расстановка/масштабы/коллизии текущего леса при уборке сохранены.

Дополнение dressing.tscn — статическая редактируемая сцена, не генератор карты.
Растения представлены небольшими переиспользуемыми сценами; пни/верстак/дрова
используют тот же WorldCover, что остальные укрытия. YoungPine меняет только
размер рисунка/своего footprint, без масштабирования физического тела. Мелкие
детали пола вынесены ниже актёров через z_index; группы растений участвуют в Y-sort.
Новые поверхности/контактные шорохи будут подключены после WAV, а не через
зависимость механик от имени сцены. tools/build_forest_details.py строит только
атласы из details.png; ни PNG, ни расстановку не перезаписывает.

PixelActorVisual читает движение и направление, но не управляет вводом/уроном/AI.
Три ракурса × четыре позы с зеркалированием дают четыре направления. Тень привязана
к видимой области кадра с учётом AtlasTexture.margin: у ступней стоя, под телом
после fallen. Полноценная анимация смерти пока заменена поворотом позы.
ActorHurtbox принимает урон по силуэту отдельно от круга движения радиусом 15 px.
Корень Player/Enemy — точка земли у ног. Круг движения/NavigationAgent, сортировка,
расстояния взаимодействий и выбрасывание используют эту же точку. Aim с телом и
оружием находится на (0,-30), камера/надписи согласованы с положением рисунка.
Пути в .tscn: Aim/Weapon и Aim/BodyVisual; старый SortAnchor удалён.
PixelActorVisual получает actor/contact_shadow явно через Inspector; стоящий
спрайт привязан к Aim, лежащий опускается на землю. Тень имеет z_index=-1.

Это одна 2D-плоскость физики, не слои высоты. weapon.try_fire принимает координаты
на земле и пускает луч от центра коллизии, исключая собственные body/hurtbox.
Player преобразует координату мыши через weapon.aim_from_screen. Трассер и
предупреждение охранника рисуются с визуальным смещением оружия; события попадания/
выстрела и AI остаются на плоскости физики. Для нынешних персонажей смещение 30 px.
ActorHurtbox — проекция силуэта на ту же плоскость, а не второй блокирующий объём.
У лута угол выбора считается от визуального Aim к предмету (как направление
курсора), дистанция и проверка стены — от точки земли. Не смешивать эти две задачи.
В лесной сцене положения актёров/их маркеров переведены +30 по Y, сохранив прежнее
положение стоящих рисунков и композицию камеры. Исходные дом/брёвна не сдвигались.
Сундук WoodCache отодвинут на 20 px вправо: старый зазор ровно 30 px зажимал тело
диаметром 30 px. Новые дрова/пень отодвинуты из тесного скопления.
WorldCover задаёт основание на земле/материал, Sprite — приподнятый рисунок.
Прямоугольное основание меняется через Size; для неровной формы Footprint Shape
принимает штатный Shape2D вместо прямоугольника (камни используют ConvexPolygonShape2D).
Не обводить коллизией весь спрайт: его верх должен перекрывать ноги при подходе
с севера. Форму/опору настраиваем один раз в общей сцене типа, затем наследуем
во всех экземплярах; универсально вычислить основание по alpha невозможно.
До тиражирования нового типа в уровне проверяем реальный контакт со всех сторон,
для неровной формы — с разными выступами, затем отход, перекрытие ног, проходы,
навигацию и попадания. Варианты размера проходят ту же проверку. Это этап подготовки
готового игрового объекта после генерации PNG; одинаковая доля высоты коллизии
для сундука, камня и стола не заменяет форму основания.
Сундук имеет основание 40×16 и отдельно поднятый Sprite; локальные копии его
формы из карты удалены. Пень/верстак/дрова сохраняют принятые формы/рисунки.
CoverOcclusion ослабляет перекрывающий спрайт, не отключая коллизии.
Высоты/3D-баллистики нет.

## Проверки и изменения

tests/fixtures/system_yard.tscn сохраняет известные расстояния/укрытия для тестов
боя, навигации, инвентаря и UI. Использует текущие Player/Enemy/LootContainer.
Старые декорации, пол, рисованные заглушки персонажей и контейнеров удалены.
Мишень и простые прямоугольники — измерительные объекты тестов, не альтернативные
ассеты игры. Производственный код не должен ссылаться на tests/fixtures.
Фактический цикл базы/рейда и кадры оформления проверяются на forest_dusk.tscn.

- Расстановка/камера — в карте; прямоугольное основание — Size, неровное — Footprint Shape.
- PNG и сцены не перезаписываются tools/build_dusk_art.py: он только подготавливает
  атласы/кадры и метаданные. Не запускать его как генератор уровня.
- При замене удалять старые ресурсы, обработчики и проверки только отвергнутого вида;
  поведенческие регрессии сохранять. После значимых изменений — tools/check.ps1.
- Старые игровые варианты восстанавливать из истории, не хранить runtime-дубли.
  Коммит — после предложения названия/состава и отдельного подтверждения владельца.
