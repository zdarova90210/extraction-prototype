# Организация проекта

Структура должна помогать менять игру небольшими проверяемыми частями.
Используем обычные сцены/узлы/Resources Godot; отдельный слой вводим при
существующей обязанности или повторении, без универсального игрового фреймворка.
Править .tscn текстом допустимо: результат остаётся редактируемой сценой.

## Карта ответственности

| Часть | Ответственность |
| --- | --- |
| scenes/base.tscn + scripts/base.gd | Схрон, выбор тестовой локации, интерфейс сохранённого прогресса |
| scenes/test_yard.tscn / forest_post.tscn | Сохранённая расстановка, коллизии, патруль, добыча и выход |
| scripts/raid_room.gd | Связывает актёров, HUD, инструменты и завершение рейда |
| scripts/test_yard.gd | Тонкая точка входа исходного полигона, наследует RaidRoom |
| scenes/raid_hud.tscn | Общий HUD, добыча, пауза, экран смерти; без копии для каждой карты |
| scenes/player.tscn / enemy.tscn | Актёры с движением/AI, оружием, звуком, взаимодействиями |
| scripts/weapon.gd | Общая стрельба, попадания, патроны и перезарядка |
| Inventory / ItemUse / LootInteraction | Владение вещами, применение и выбор/перенос в мире |
| RaidProgress / AudioSettings / DisplaySettings | Отдельные долгоживущие обязанности, без знаний о лесных спрайтах |
| scenes/forest/ | Варианты оформления и переиспользуемые предметы окружения |
| assets/art/forest_post/ | Четыре исходных PNG, точные промпты и происхождение |
| resources/art/forest_post/ | Области атласов, кадры анимаций и локальные шейдеры |

## Общий контракт комнаты

Комнаты сохраняют именованные узлы Player, Navigation, GuardSpawns, TestEnemies,
LootContainers, ExtractionZone и HUD. RaidRoom соединяет их сигналы при старте.
Target необязателен, guard_scene выбирается в Inspector. Тестовая расстановка
полигона сохраняется при выделении общих компонентов.

Актёр/оружие/инвентарь не знают имени комнаты. Не копировать их логику в новую
карту; новый уровень задаёт данные и связывает существующие компоненты.
Постоянные объекты уже видны в редакторе. Во время игры появляются только
динамические вещи, добавленные охранники и краткоживущие эффекты.

## Внешний вид и физика

Лесные Player/Guard наследуют существующие сцены. PixelActorVisual подменяет
геометрический рисунок, сохраняя flash_hit/fallen, анимацию по пройденной дистанции
и отдельное оружие. Он не управляет вводом, уроном, AI или расходом патронов.
Три нарисованных ракурса с зеркалированием дают четыре направления, по четыре
позы шага; диагональные виды и полноценная анимация смерти пока не подготовлены.

ActorHurtbox — не блокирующая движение область получения урона по стоящему
силуэту. Круг движения 15 px сохраняется. Area использует прежний слой актёра
и делегирует take_damage; смерть отключает её, восстановление включает обратно.
Weapon допускает попадания в такие Area, по-прежнему выбирая первую преграду.

WorldCover — статическая коллизия и материал попадания; Sprite2D — оформление.
CoverOcclusion управляет только прозрачностью переднего рисунка над игроком.
Они не подменяют друг другу правила прохода/выстрела. Корни актёров остаются
в прежней 2D-плоскости; Y-сортировка не вводит высоту или 3D-баллистику.
PixelLootContainer наследует поиск/передачу и заменяет только рисунок ящика.

## Изменения и откат

- Расстановка — в комнате; вид дома/дерева — в отдельной сцене forest/.
- Боевые правила — в общем компоненте с проверкой обеих комнат.
- PNG не разрезаются/перерисовываются инструментом сборки. build_forest_art.py
  читает alpha и создаёт AtlasTexture/SpriteFrames; это инструмент подготовки,
  не код генерации уровня при запуске.
- Эксперимент с оформлением можно заменить отдельно от механик/сохранений.
  Общий код не обрастает условиями «если лесной стиль».
- Убирать заменённые файлы/сигналы и обновлять затронутые проверки/документацию.
  Коммит — только после предложения названия/состава и отдельного подтверждения.
